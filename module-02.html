1. Why this matters when you build

In Module 01, you learned this workflow structure:

Trigger -> Input -> Logic -> Action -> Output -> Review

That map is still correct. But a no-code builder will not ask only, “What should happen?” It will ask you to choose a trigger, connect an account, map fields, choose an action, inspect outputs, and handle errors.

Module 01 view

Inquiry submitted -> classify inquiry -> create lead -> notify sales -> review.

Module 02 view

What fields came in? What format are they in? Which step receives them next? Does the CRM require email? What comes back after the record is created?

A workflow can look correct on paper and still fail during the build because a required field is missing, the next tool expects a different format, the account does not have permission, or AI returns text the next step cannot use.

Good workflow design depends on knowing what each step needs to receive, send, use, and return.
Clarification

2. Automation can happen inside one tool or across tools

Automation does not always mean connecting several platforms.

Inside one tool

  • A spreadsheet calculates a status
  • An email rule sorts incoming messages
  • A form routes someone based on an answer
  • A database updates a field when a record changes

Across tools

  • A form collects information
  • An AI step summarizes or classifies it
  • A CRM or tracker stores the result
  • An email or notification sends the output

Both are automation. In any automation, something is captured, checked, changed, sent, saved, updated, routed, or prepared for review.

The number of tools is not the main issue. The main issue is whether the right information reaches the right step in a usable form.

When you start building, tool communication usually appears through a visual interface. You may not see raw technical code. You will see labels, fields, menus, run results, and errors.

What you seeWhat it means

Connection / connected accountPermission for one tool or step to access another system.
ActionThe thing the next system is being asked to do.
Mapped fieldsThe information being passed from one step to another.
Webhook URLA receiving address where one system can send event data.

The visual interface makes automation easier to build. It does not remove the structure underneath.

Use this pattern throughout the module:

Captured -> Structured -> Passed -> Received -> Used

Click each part below.

Captured

The workflow receives information from a form, email, file, message, spreadsheet row, database record, AI output, or manual entry.

APIs, webhooks, JSON, field mapping, permissions, and run logs all connect back to one question:

Can the next step receive and use the information correctly?
Core Mechanics

5. Three mechanics to recognize

These are not separate apps. They are parts of how automation systems exchange information.

MechanicProfessional definitionPractical role
APIAn application programming interface: a defined way for one software system to interact with another software system.Used when one system needs another system to retrieve data, create something, update something, send something, or return a result.
WebhookAn event-based message sent from one system to another when something happens.Used when an event should automatically start or continue a workflow.
JSONA structured data format used to organize and transmit information as labeled values.Used so systems can read, pass, and use information consistently.

API: one system asks another system to do something

A raw API request can look like this:

POST https://api.examplecrm.com/v1/leads
Authorization: Bearer API_KEY
Content-Type: application/json

{
  "name": "Maria Santos",
  "email": "maria@email.com",
  "message": "I want to ask about pricing.",
  "source": "Website form"
}

The learner does not need to write this in this track. The point is to recognize the parts that affect whether the workflow works.

PartWhat it controls
MethodThe action type, such as create, retrieve, update, or delete.
EndpointThe destination, usually a URL or URL path, where the request is sent.
AuthenticationThe credential, such as an API key, token, or connected account.
Body / payloadThe actual information being sent.
ResponseWhat comes back after the request is processed.

In a no-code builder, the same interaction may appear as: App: CRM. Action: Create Lead. Connection: CRM account. Fields: Name, Email, Message, Source.

Design question: What does the receiving system require in order to complete this action?

Webhook: one system tells another system something happened

A webhook is commonly used when an event should start or continue a workflow.

This happened. Here is the information.

Example events: form submitted, payment received, file uploaded, new message arrived, status changed, booking created, lead captured.

In no-code tools, a webhook may appear as a webhook URL, custom webhook, trigger URL, instant trigger, “send data to this URL,” or “watch for incoming data.”

https://hook.exampleautomation.com/abc123
Design question: What event should start or continue the workflow, and what information must come with that event?

JSON: information organized as labeled values

JSON is a common structure for information being passed between automation steps.

{
  "category": "sales",
  "urgency": "normal",
  "summary": "Maria is asking about pricing.",
  "recommended_owner": "Sales Team"
}

This matters because the next step can use category for routing, urgency for escalation, summary for the notification, and recommended_owner for assignment.

Design question: What labels and formats does the next step need in order to use the information correctly?
Field Mapping

6. Matching information between steps

Field mapping means connecting information from one step to the correct field in another step.

Form collects

Full Name: Maria Santos
Email Address: maria@email.com
Inquiry: I want to ask about pricing.

CRM expects

Name
Email
Message

The builder maps Full Name to Name, Email Address to Email, and Inquiry to Message.

This becomes risky when field names, formats, or meanings are unclear.

FieldPossible confusion
ContactCould mean phone, email, or person name.
DateCould mean submitted date, appointment date, or due date.
StatusCould mean lead status, payment status, or task status.
OwnerCould mean salesperson, account manager, or reviewer.
Design question: Does each step know exactly what each field means and where it should go next?
Access

7. Authentication and permissions

Tool communication often requires permission. A connected account, API key, access token, or authorization screen tells the receiving system that the request is allowed.

Read

The workflow can retrieve existing information.

Create

The workflow can create a new record, message, file, task, or event.

Update

The workflow can change an existing record, status, row, or document.

A workflow can be designed correctly and still fail because the connection does not have the right access.

Permission issues usually appear as access denied, unauthorized, invalid token, expired connection, insufficient permissions, account not connected, or app not approved.

Design question: Does this workflow have the right access to perform the action it needs to perform?
Troubleshooting

8. Common communication failures

Most automation failures are not mysterious. They usually come from a specific handoff point.

Failure pointWhat it means
Trigger did not startThe event did not happen, or the trigger was not set correctly.
Missing fieldRequired information was not captured or passed.
Wrong formatThe next step rejected the value because it was formatted incorrectly.
Wrong field mappingThe right information went to the wrong place.
Permission blockedThe connection does not have access to perform the action.
Duplicate recordThe system received information it already had.
AI output unusableAI returned text the next step could not read or use.
Response not handledThe workflow did not define what to do after success or error.

The practical troubleshooting question is:

Where did the handoff break?
Lead did not appear in CRM.Check whether required fields reached the CRM step.
Workflow never started.Check event source, trigger setup, or webhook URL.
AI category cannot be used in routing.Check whether AI returned a consistent field like category.
